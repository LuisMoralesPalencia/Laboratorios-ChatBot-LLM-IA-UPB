# Rúbrica interna del proyecto final

Nivel de acceso: docente. No compartir con estudiantes.

## Criterios y pesos

| Criterio | Peso |
|---|---|
| Arquitectura: componentes con responsabilidad clara y diagrama coherente con el código | 25 % |
| Funcionalidad: el sistema responde las preguntas de la demostración | 25 % |
| Evaluación con datos: conjunto fijo de preguntas y métricas | 20 % |
| Sustentación individual | 30 % |

## Reglas internas de calificación

- Si un integrante no puede explicar un componente que aparece en el código, su nota de
  sustentación tiene un máximo de 2.5.
- Si el repositorio contiene una API key o un archivo .env, se descuentan 1.0 puntos de la nota
  del proyecto.
- Señales de copia entre grupos: prompts idénticos, mismos nombres de variables poco comunes o la
  el nombre de un integrante de otro grupo en el system prompt. En ese caso se cita a sustentación adicional.
- La nota mínima de la sustentación para aprobar el proyecto es 3.0, independientemente del resto
  de criterios.
